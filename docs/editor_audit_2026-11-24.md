# Проверка редактора блоков — 24 ноября 2026

Проверка выполнена на Linux/Python 3.12 с `QT_QPA_PLATFORM=offscreen`. Это проверка поведения GUI и его обработчиков; запуск STAR-CCM+ на Windows в неё не входит.

## Найдено и исправлено

1. **Выравнивание смешанных значений по первому блоку.** Раньше редактор вычислял изменения только сравнением с первым выбранным блоком. При выборе ni=8/12 ввод ni=8 мог оставить второй блок с ni=12. Теперь учитывается явно отредактированное поле, в том числе повторный выбор текущего режима в списке. Целочисленное поле сообщает и о завершённом вводе смешанного значения без изменения его опорного числа. Остальные настройки блоков сохраняются.
2. **Некорректный ввод ядра.** Ошибка чтения числа могла выйти из Qt-обработчика. Теперь она отображается в статусе; полная сетка инвалидируется, а пригодный пристеночный слой остаётся для повторного заполнения после исправления. Неактивные параметры не учитываются.
3. **Незавершённый ввод перед прямым экспортом.** Проверка актуальности теперь считывает активные поля стенки, включая черновики, а для локального ядра учитывает неприменённый ввод отдельно. Старую полную сетку нельзя экспортировать до перестроения/повторного заполнения. Проверка только параметров ядра не сбрасывает слой. Отказ от заполнения после изменения стенки происходит раньше, с сообщением в журнале; лишнее критическое окно не требуется.

## Регрессионные сценарии

В `tests/test_editor_audit.py` добавлены проверки:

- ni=8/12 → ввод 8 → оба блока ni=8;
- h1=3/4 мкм → ввод 3 → оба блока h1=3 мкм;
- ядро 3/5 слоёв → ввод 3 → оба блока по 3 слоя;
- повторный выбор режима первого блока применяется к остальным;
- некорректный рост ядра в общей и локальной областях блокирует экспорт, сохраняет слой, исправление и заполнение восстанавливают полную сетку;
- прямой экспорт учитывает незавершённые значения стенки и локального ядра до открытия диалога пути.

Тесты также проверяют, что исключения не вышли в `sys.excepthook` из Qt-сигналов. Ранее существующие проверки геометрии, построения, проектов, наследования, диагностики, отмены/экспорта и генерации макроса остаются в полном прогоне.

## Границы проверки

Не подтверждены новой ручной проверкой: отображение на пользовательском Windows, производительность на пользовательской большой сетке и выполнение макроса в STAR-CCM+. Неконформные CFD-интерфейсы внутри подканала по-прежнему не экспортируются; см. [локальные настройки](local_block_settings.md).

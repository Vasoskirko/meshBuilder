# Свойства воды: IF97 + IAPWS 2008/2011

Вычисления в `fluid_properties.water_iapws97(t_c, p_mpa)` используют Python-пакет `iapws==1.5.5`:

- плотность и теплоёмкость — IAPWS-IF97, регион 1;
- динамическая вязкость — IAPWS R12-08 (формулировка 2008 года);
- теплопроводность — IAPWS R15-11 (формулировка 2011 года), с явным выбором учёта критического усиления;
- кинематическая вязкость `nu = mu / rho`, число Прандтля `Pr = mu * cp / lambda`.

Вязкостный множитель критического усиления для промышленного применения опущен согласно R12-08. Для теплопроводности по умолчанию используется фоновая часть `lambda0*lambda1` без критического усиления, согласующаяся с предоставленным пользователем полем STAR. Полный промышленный вариант `lambda0*lambda1 + lambda2`, реализованный в `IAPWS97` пакета, сохранён отдельной опцией. Критическая область не входит в поддерживаемый здесь регион 1. Пакет `iapws` — сторонняя реализация опубликованных формулировок, а не библиотека, выпущенная самой IAPWS.

## Источники и контрольные точки

- [IAPWS R12-08: viscosity](https://iapws.org/technical-guidance/release/viscosity) — таблица 4: точки T, rho, mu без критического усиления.
- [IAPWS R15-11: thermal conductivity](https://iapws.org/technical-guidance/release/ThCond) — таблица 4: точки T, rho, lambda без критического усиления; раздел 3: промышленное применение.
- [Документация реализации iapws](https://iapws.readthedocs.io/en/latest/) и [исходный код IAPWS97](https://iapws.readthedocs.io/en/latest/_modules/iapws/iapws97.html).

Автотесты сравнивают транспортные ядра установленной версии с числовыми точками официальных таблиц. Отдельно проверяются результаты публичной функции по T/P, включая переход единиц, свойства на насыщении и передачу данных через GUI/y+ в генератор макроса. Контрольные точки по T/rho для транспортных ядер не означают расширения диапазона публичного API.

Примеры результатов публичной функции при `conductivity_model="full"` (полный вариант с усилением):

| T, °C | P, МПа | rho, кг/м³ | mu, Па·с | lambda, Вт/(м·К) | Pr |
|---|---|---|---|---|---|
| 25 | 0.1 | 997.047435 | 8.90022551e-4 | 0.606515827 | 6.13666651 |
| 300 | 15 | 725.553275 | 8.83477572e-5 | 0.563209240 | 0.858994748 |
| 350 | 100 | 762.334558 | 9.59150185e-5 | 0.608499831 | 0.725835269 |

Это значения выбранной промышленной реализации, а не утверждение о нулевой физической неопределённости корреляций.

## Диапазон и единицы

Сохранён прежний интерфейс: температура в °C, абсолютное давление в МПа. Поддерживается жидкая вода при `0 <= T <= 350 °C`, `0 < P <= 100 MPa` и `P >= Psat(T)`. Пар, двухфазная смесь, регион 3 и сверхкритическая вода этим API не поддерживаются; выход за диапазон вызывает ValueError. Более широкий диапазон пакета `iapws` намеренно не открывается автоматически.

Ровно на линии насыщения выбирается насыщенная жидкость через `x=0`. Классификация только по T/P на машинной границе может выбрать пар — это обнаружено, в частности, при 100 °C. Для численно неразличимых состояний чуть выше Psat применяется та же жидкая граница; давления ниже вычисленного Psat по-прежнему отклоняются.

Возвращаемые единицы:

| Ключ | Единицы |
|---|---|
| `density` | кг/м³ |
| `dyn_vis` | Па·с |
| `kin_vis` | м²/с |
| `cp` | Дж/(кг·К); значение пакета в кДж/(кг·К) умножается на 1000 |
| `lambda` | Вт/(м·К) |
| `prandtl` | безразмерное |

Свойства возвращаются как обычные Python float без предварительного округления; GUI форматирует только отображение. В словарь также входят выбранный `conductivity_model` и исходные `t_ref_c`, `p_ref_mpa`, чтобы экспорт использовал то же состояние. Сохранены прежние ключи, расчёт газов не изменён.

## Обновление и совместимость

После получения этой версии обновите зависимости:

```bash
python -m pip install -r requirements.txt
```

Нет скрытого возврата к старым эмпирическим формулам при отсутствии пакета. Версия закреплена для воспроизводимости расчётов. CI устанавливает зависимости из того же requirements.txt.

Пересчитайте y+ и перестройте пристеночный слой, если он был рассчитан по прежним свойствам: новые mu/nu могут изменить рекомендуемый h1. Не подменяйте этим результатом автоматически уже построенную сетку.

Изменение относится к свойствам и расчёту y+ в meshBuilder. Оно не выбирает методы материала внутри STAR-CCM+: для режима IAPWS в STAR по-прежнему нужно проверить отдельные методы вязкости и теплопроводности. Для режима постоянных свойств экспорт получает новые рассчитанные значения; форматирование чисел определяется версией генератора макроса.


## Согласование с полем теплопроводности STAR

Пользователь получил в скалярной сцене после инициализации при 300 °C, абсолютном давлении 15 МПа: mu≈8.835e-5 Па·с, lambda≈0.5574 Вт/(м·К), rho≈725.553 кг/м³, cp≈5476.016 Дж/(кг·К).

Установлено численно, что `iapws._iapws._ThCond(rho,T)` без переданной фазы даёт **0.557436764298241 Вт/(м·К)**: это фоновая часть опубликованной корреляции R15-11. Полное `IAPWS97.k`, добавляющее критический вклад по промышленному варианту, равно **0.5632092396757247 Вт/(м·К)**. Разница не связана с давлением в Па/МПа или округлением температуры. Плотность, теплоёмкость и вязкость для обоих вариантов одинаковы.

В калькуляторе y+ появился выбор «Теплопроводность воды»:

| Вариант | Ключ API | lambda при 300 °C / 15 МПа | Pr |
|---|---|---|---|
| Без критического усиления — по умолчанию для согласования с приведённым полем STAR | `background` | 0.557436764298241 | 0.867889974186248 |
| С критическим усилением — полный промышленный вариант | `full` | 0.563209239675725 | 0.858994748125611 |

Пример явного вызова: `water_iapws97(300, 15, conductivity_model="background")`.
Неизвестный вариант вызывает ValueError. Выбор сохраняется в состоянии калькулятора, восстанавливается при повторном открытии, отображается в описании свойств и влияет на экспортируемую lambda и связанный Pr. В обоих случаях `Pr = mu*cp/lambda`; коэффициент подгонки к единственной точке не применяется. Оценка y+ зависит от rho и mu, поэтому переключение только усиления lambda не должно менять её.

Используется документированное ядро `_ThCond` закреплённой версии `iapws==1.5.5`; его имя приватное, поэтому обновление зависимости требует повторной проверки адаптера и контрольных таблиц. Вариант `full` продолжает использовать публичное `IAPWS97.k`.

Совпадение фона с пользовательским значением проверено для предоставленной точки, а не для всех настроек/версий STAR. Для полного подтверждения согласованности следует сверить ещё несколько жидкофазных T/P и выбранный нативный Method материала. Сам выбор в meshBuilder не переключает метод внутри STAR автоматически.


### Вторая точка из скалярной сцены пользователя

При 290 °C и 16.2 МПа текущая формула без усиления (без изменения коэффициентов между точками) даёт:

| Свойство | STAR, передано пользователем | meshBuilder background |
|---|---|---|
| Плотность, кг/м³ | 747.339 | 747.3390805476422 |
| Динамическая вязкость, Па·с | 9.27175e-5 | 9.271750031043231e-5 |
| Cp, Дж/(кг·К) | 5225.098 | 5225.098000687439 |
| Теплопроводность, Вт/(м·К) | 0.57532 | 0.5753275671409854 |

Первые три величины согласуются с переданной точностью. Остаточное расхождение lambda равно 7.56714e-6 Вт/(м·К), около 0.001315%; оно немного превышает половину последнего указанного разряда и **не объявляется доказанным округлением**. Для установления причины нужны более точные данные lambda и выбранный Method материала STAR. Полный вариант с усилением даёт 0.5801910046304146 Вт/(м·К), то есть иное существенно большее расхождение. Режим/версию самой программы также надо учитывать, если пользователь видит другие числа.

Эта точка добавлена в регрессионную проверку с явным сохранением остаточного расхождения. Ни формула, ни её коэффициенты по этой точке не менялись. Совпадение нескольких чисел пока не устанавливает точное название/реализацию нативного метода STAR во всём диапазоне.

Пользователь затем уточнил показания своей копии meshBuilder в той же точке: rho=747.34, mu=9.447e-5, cp=5225.1, lambda=0.582, Pr=0.85. Они воспроизводятся прежним кодом: эмпирическая mu=9.44673336605584e-5, полиномиальная lambda=0.5824, Pr≈0.847529. Это указывает на запуск старого модуля, а не на ошибку новой фоновой формулы в этой точке. Для проверки нужно обновить запускаемую копию до ветки PR №21 и зависимости, затем заново открыть калькулятор; старый процесс Python продолжает использовать уже импортированный код.


## Поля свойств и линия насыщения в калькуляторе

Строка «Справочно (CFD)» заменена отдельными полями с единицами: кинематическая вязкость, Cp, lambda, Pr, удельная энтальпия. Как и рассчитанные rho/mu, они доступны для чтения/копирования. У вычисляемых величин нет ручного редактирования. Методы формулировок показаны отдельной подписью. Отображение mu стало точнее для сравнения со STAR; внутренние значения по-прежнему не округляются.

Энтальпия текущего состояния — `enthalpy`, **Дж/кг в API** и **кДж/кг в GUI**. Используется h из IF97, а не приближение Cp*T. При сравнении со STAR необходимо проверить согласованность точки отсчёта энтальпии: разность абсолютных h при другом термодинамическом нуле не означает разность Cp.

В отдельном блоке «Линия насыщения воды (IF97)» показаны:

- `saturation_pressure_mpa`: Psat при текущей T, МПа;
- `saturation_temperature_c`: Tsat при текущем P, °C;
- `pressure_margin_mpa`: P−Psat(T), МПа;
- `subcooling_k`: Tsat(P)−T, K;
- `saturated_liquid_density`, `saturated_vapor_density`: rho′/rho″ при **заданном P**;
- `saturated_liquid_enthalpy`, `saturated_vapor_enthalpy`: h′/h″ при заданном P, Дж/кг в API, кДж/кг в GUI;
- `latent_heat`: h″−h′ при заданном P, Дж/кг в API, кДж/кг в GUI.

Например, при T=300 °C, P=15 МПа: h≈1338.063261 кДж/кг, Psat≈8.58770833 МПа, Tsat≈342.157871 °C, недогрев≈42.157871 K, запас давления≈6.41229167 МПа. На линии насыщения при **15 МПа**: rho′≈603.513927 кг/м³, rho″≈96.710941 кг/м³, h′≈1610.151786 кДж/кг, h″≈2610.864759 кДж/кг, r≈1000.712973 кДж/кг. Это состояния на границе при P, а не свойства текущей жидкости при 300 °C.

Две разные задачи насыщения подписаны явно: Psat(T) и Tsat(P) не задают одно и то же состояние, если текущее состояние — сжатая жидкость. Параметры насыщенных фаз при P вычисляются только от тройного давления 0.000611657 МПа до критического **строго ниже 22.064 МПа**. За этими пределами они возвращаются как None, GUI показывает прочерк и причину; Psat(T) и P−Psat(T) остаются доступны в прежнем диапазоне IF97. У критической точки отдельные жидкая и паровая фазы не назначаются искусственно.

Для P между Psat(350 °C) и критическим Tsat(P) может быть выше 350 °C: в этом случае справочная граница насыщения вычисляется пакетом IF97 в соответствующем регионе. Диапазон **текущего** состояния воды остаётся Region 1, 0–350 °C; запрос текущего состояния при 360 °C по-прежнему отклоняется. Линия плавления/лёд не рассчитываются.

При выборе газа доступны рассчитанные Cp/lambda/Pr/gamma и nu=mu/rho; энтальпия и водяное насыщение не выдумываются. При ручном rho/mu можно вычислить nu, остальные отсутствующие свойства показываются прочерком. При ошибке T/P вычисленные поля очищаются и применение h1 блокируется, чтобы не выдавать старые свойства за новые. При ошибке только параметров потока корректные теплофизические свойства остаются видимыми.

Диалог получил вертикальную прокрутку, а кнопки применения/закрытия остаются снаружи области прокрутки. Дополнительные свойства не превращаются автоматически в новые отчёты/мониторы STAR и не меняют начальные условия макроса.

## Отдельное окно свойств и единая ветка проверки

Полный список свойств вынесен из калькулятора y+ в отдельное окно «Свойства теплоносителя и линия насыщения». В основном калькуляторе оставлены выбор среды, T/P, rho, mu, вычисленная nu, геометрия, параметры потока и результат h1.

Кнопка «Все свойства теплоносителя и насыщение…» открывает немодальное окно: можно одновременно менять T/P в калькуляторе и видеть обновление свойств. Там находятся Cp, lambda, Pr, h, все параметры насыщения и переключатель учёта критического усиления lambda. Настройка lambda общая и сохраняется в том же состоянии калькулятора. Она влияет на lambda/Pr и экспортируемые свойства, но не на rho/mu/h1. Закрытие окна свойств не применяет h1; закрытие калькулятора закрывает дочернее окно. Недоступные/ошибочные свойства очищаются и в открытом окне.

Причина «пропавших» настроек экспорта была в ветках: первоначально ветка свойств была создана от main до включения PR №20. После того как PR №20 вошёл в main, актуальный origin/main включён в ветку fix/iapws-water-transport-properties. В ней теперь одновременно присутствуют новый расчёт воды/отдельное окно свойств и все шесть вкладок экспорта STAR. Это обновление ветки PR №21; сам PR №21 не сливался в main.

Для проверки используйте одну и ту же копию репозитория и ветку:

```bash
git fetch origin
git switch fix/iapws-water-transport-properties
git pull --ff-only
python -m pip install -r requirements.txt
python bundle_subchannel_builder.py
```

Перед запуском закройте прежний процесс приложения. Обновление ветки не загружает новые модули в уже работающий Python.

Переключатель λ теперь подписан понятнее: «Базовая теплопроводность λ» и «Теплопроводность λ с добавочным вкладом около критической точки». Он не переключает формулу вязкости, поэтому mu остаётся прежней. Подробности изменений построения/заполнения ядра: [bundle_build_workflow.md](bundle_build_workflow.md).

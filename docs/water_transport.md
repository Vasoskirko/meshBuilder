# Свойства воды: IF97 + IAPWS 2008/2011

Вычисления в `fluid_properties.water_iapws97(t_c, p_mpa)` используют Python-пакет `iapws==1.5.5`:

- плотность и теплоёмкость — IAPWS-IF97, регион 1;
- динамическая вязкость — IAPWS R12-08 (формулировка 2008 года);
- теплопроводность — IAPWS R15-11 (формулировка 2011 года), с явным выбором учёта критического усиления;
- кинематическая вязкость `nu = mu / rho`, число Прандтля `Pr = mu * cp / lambda`.

Вязкостный множитель критического усиления для промышленного применения опущен согласно R12-08. Для теплопроводности по умолчанию используется фоновая часть `lambda0*lambda1` без критического усиления, согласующаяся с предоставленным пользователем полем STAR. Полный промышленный вариант `lambda0*lambda1 + lambda2`, реализованный в `IAPWS97` пакета, сохранён отдельной опцией. Критическая область не входит в поддерживаемый здесь регион 1. Пакет `iapws` — сторонняя реализация опубликованных формулировок, а не библиотека, выпущенная самой IAPWS.

## Источники и контрольные точки

- [IAPWS R12-08: viscosity](https://iapws.org/technical-guidance/release/viscosity) — таблица 4: точки T, rho, mu без критического усиления.
- [IAPWS R15-11: thermal conductivity](https://iapws.org/technical-guidance/release/ThCond) — таблица 4: точки T, rho, lambda без критического усиления; раздел 3: промышленное применение.
- [Документация реализации iapws](https://iapws.readthedocs.io/en/latest/) и [исходный код IAPWS97](https://iapws.readthedocs.io/en/latest/_modules/iapws/iapws97.html).

Автотесты сравнивают транспортные ядра установленной версии с числовыми точками официальных таблиц. Отдельно проверяются результаты публичной функции по T/P, включая переход единиц, свойства на насыщении и передачу данных через GUI/y+ в генератор макроса. Контрольные точки по T/rho для транспортных ядер не означают расширения диапазона публичного API.

Примеры результатов публичной функции при `conductivity_model="full"` (полный вариант с усилением):

| T, °C | P, МПа | rho, кг/м³ | mu, Па·с | lambda, Вт/(м·К) | Pr |
|---|---|---|---|---|---|
| 25 | 0.1 | 997.047435 | 8.90022551e-4 | 0.606515827 | 6.13666651 |
| 300 | 15 | 725.553275 | 8.83477572e-5 | 0.563209240 | 0.858994748 |
| 350 | 100 | 762.334558 | 9.59150185e-5 | 0.608499831 | 0.725835269 |

Это значения выбранной промышленной реализации, а не утверждение о нулевой физической неопределённости корреляций.

## Диапазон и единицы

Сохранён прежний интерфейс: температура в °C, абсолютное давление в МПа. Поддерживается жидкая вода при `0 <= T <= 350 °C`, `0 < P <= 100 MPa` и `P >= Psat(T)`. Пар, двухфазная смесь, регион 3 и сверхкритическая вода этим API не поддерживаются; выход за диапазон вызывает ValueError. Более широкий диапазон пакета `iapws` намеренно не открывается автоматически.

Ровно на линии насыщения выбирается насыщенная жидкость через `x=0`. Классификация только по T/P на машинной границе может выбрать пар — это обнаружено, в частности, при 100 °C. Для численно неразличимых состояний чуть выше Psat применяется та же жидкая граница; давления ниже вычисленного Psat по-прежнему отклоняются.

Возвращаемые единицы:

| Ключ | Единицы |
|---|---|
| `density` | кг/м³ |
| `dyn_vis` | Па·с |
| `kin_vis` | м²/с |
| `cp` | Дж/(кг·К); значение пакета в кДж/(кг·К) умножается на 1000 |
| `lambda` | Вт/(м·К) |
| `prandtl` | безразмерное |

Свойства возвращаются как обычные Python float без предварительного округления; GUI форматирует только отображение. В словарь также входят выбранный `conductivity_model` и исходные `t_ref_c`, `p_ref_mpa`, чтобы экспорт использовал то же состояние. Сохранены прежние ключи, расчёт газов не изменён.

## Обновление и совместимость

После получения этой версии обновите зависимости:

```bash
python -m pip install -r requirements.txt
```

Нет скрытого возврата к старым эмпирическим формулам при отсутствии пакета. Версия закреплена для воспроизводимости расчётов. CI устанавливает зависимости из того же requirements.txt.

Пересчитайте y+ и перестройте пристеночный слой, если он был рассчитан по прежним свойствам: новые mu/nu могут изменить рекомендуемый h1. Не подменяйте этим результатом автоматически уже построенную сетку.

Изменение относится к свойствам и расчёту y+ в meshBuilder. Оно не выбирает методы материала внутри STAR-CCM+: для режима IAPWS в STAR по-прежнему нужно проверить отдельные методы вязкости и теплопроводности. Для режима постоянных свойств экспорт получает новые рассчитанные значения; форматирование чисел определяется версией генератора макроса.


## Согласование с полем теплопроводности STAR

Пользователь получил в скалярной сцене после инициализации при 300 °C, абсолютном давлении 15 МПа: mu≈8.835e-5 Па·с, lambda≈0.5574 Вт/(м·К), rho≈725.553 кг/м³, cp≈5476.016 Дж/(кг·К).

Установлено численно, что `iapws._iapws._ThCond(rho,T)` без переданной фазы даёт **0.557436764298241 Вт/(м·К)**: это фоновая часть опубликованной корреляции R15-11. Полное `IAPWS97.k`, добавляющее критический вклад по промышленному варианту, равно **0.5632092396757247 Вт/(м·К)**. Разница не связана с давлением в Па/МПа или округлением температуры. Плотность, теплоёмкость и вязкость для обоих вариантов одинаковы.

В калькуляторе y+ появился выбор «Теплопроводность воды»:

| Вариант | Ключ API | lambda при 300 °C / 15 МПа | Pr |
|---|---|---|---|
| Без критического усиления — по умолчанию для согласования с приведённым полем STAR | `background` | 0.557436764298241 | 0.867889974186248 |
| С критическим усилением — полный промышленный вариант | `full` | 0.563209239675725 | 0.858994748125611 |

Пример явного вызова: `water_iapws97(300, 15, conductivity_model="background")`.
Неизвестный вариант вызывает ValueError. Выбор сохраняется в состоянии калькулятора, восстанавливается при повторном открытии, отображается в описании свойств и влияет на экспортируемую lambda и связанный Pr. В обоих случаях `Pr = mu*cp/lambda`; коэффициент подгонки к единственной точке не применяется. Оценка y+ зависит от rho и mu, поэтому переключение только усиления lambda не должно менять её.

Используется документированное ядро `_ThCond` закреплённой версии `iapws==1.5.5`; его имя приватное, поэтому обновление зависимости требует повторной проверки адаптера и контрольных таблиц. Вариант `full` продолжает использовать публичное `IAPWS97.k`.

Совпадение фона с пользовательским значением проверено для предоставленной точки, а не для всех настроек/версий STAR. Для полного подтверждения согласованности следует сверить ещё несколько жидкофазных T/P и выбранный нативный Method материала. Сам выбор в meshBuilder не переключает метод внутри STAR автоматически.

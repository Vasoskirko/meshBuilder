# Проверка экспорта Fuse в STAR-CCM+

## Группировка поверхностей

В режиме Fuse число внешних зазоров и стенок зависит от выбранной сборки. Правило «три наименьшие площади — зазоры» не применяется. Макрос сопоставляет площадь и центроид каждой боковой поверхности с геометрией фактически экспортированных блоков: половинами/полными гранями зазоров и дугами физических стержней. При неоднозначном или отсутствующем совпадении выполнение останавливается с сообщением о поверхности, а не присваивает ей тип стержня наугад.

Имена `rod_R<id>` соответствуют идентификаторам стержней геометрической модели, а не порядку сортировки площадей. В Fuse вариант «Секторы по 60°» недоступен: сохранение таких секторов после слияния не реализовано. Доступны группировка по физическим стержням и общая стенка. Угловое разбиение импортированной поверхности для её распознавания не является гарантией сохранения исходных секторов 60°.

Типы физических граничных условий пользователь задаёт вручную. Именование `Inlet`, `Outlet`, `rod_...`, `sym/per` само по себе не назначает вход, выход или симметрию.

## Сечения и зонды

После Fuse сохраняется один физический регион `TVS_Assembly`, но для анализа исходных подканалов создаются отдельные Threshold Parts `Subchannel_N_Domain`. Маска выбирает ячейки внутри исходного треугольника между центрами стержней. Номера соответствуют порядку подканалов в экспортированной сетке; пропущенные периферийные подканалы в него не включаются.

Индивидуальные сечения используют соответствующий Domain, а не весь монолит. Осевые зонды создаются по центру каждого выбранного исходного подканала. Общие сечения используют всю сборку. Ключевые положения Z=0, L/2, L не дублируются, если входят в регулярную серию. Для одного подканала совпадающее общее сечение переиспользуется. Отчёты расхода по подканалам требуют входного/выходного сечения даже при отключённой визуальной серии сечений.

## Отчёты и ошибки

- `MassFlow_Inlet_Total`, `MassFlow_Outlet_Total`: расходы по внешним входным и выходным поверхностям.
- `MassFlow_In_SubN`, `MassFlow_Out_SubN`: расходы через сечения исходного подканала. Нормаль всех таких сечений направлена по +Z; их знак не равнозначен знаку внешней нормали входной границы.
- `Imbalance_MassFlow`: `100 * abs(m_in + m_out) / max(abs(m_in), 1e-30)`. Для внешних границ используются знаковые расходы: вход обычно отрицательный.

При включённой энергии (или IAPWS, который включает энергию) также запрашиваются:

- `TotalEnthalpy_Inlet`, `TotalEnthalpy_Outlet`: средняя по массовому расходу полная энтальпия (`TotalEnthalpy`).
- `Energy_Flow_Inlet_Total`, `Energy_Flow_Outlet_Total`: массовый расход, умноженный на среднюю полную энтальпию.
- `Heat_Flux_Rods_Total`: интеграл `BoundaryHeatFlux` по стенкам стержней, мощность, а не плотность потока.
- `Heat_Flux_Walls_Total`: интеграл того же поля по всем внешним боковым стенкам, включая несопряжённые зазоры.
- `Imbalance_Energy`: относительный модуль `H_in + H_out - Q_walls`. Предполагается, что `BoundaryHeatFlux` положителен при подводе тепла к жидкости. Нормирователь — максимум модулей потоков энтальпии, тепловой мощности и `1e-30`.

Эта энергетическая невязка — диагностический стационарный баланс переноса полной энтальпии и тепла через боковые стенки. Она не учитывает накопление энергии в нестационарном расчёте, объёмные источники или дополнительные виды работы/переноса. Знак `BoundaryHeatFlux`, доступность полей и применимость такого баланса к выбранным физическим моделям необходимо проверить в целевой версии STAR-CCM+. Нулевые начальные значения при всех границах Wall не доказывают сходимость или выполнение энергетического баланса.

Для каждого успешно настроенного отчёта отдельно создаётся монитор. Ошибка монитора не прерывает создание следующих отчётов. Недоступное поле или ошибка STAR API выводится как `[!]` с именем объекта. Итоговый вывод показывает число созданных отчётов и мониторов, а не безусловное сообщение о готовности к расчёту.

## Приёмка в STAR-CCM+ 2602

Использовать новую пустую симуляцию и новый комплект XYZ/Java; старые макросы не обновляются автоматически.

1. Экспортировать два соседних внутренних подканала в Fuse, с одинаковыми параметрами блоков.
2. Проверить один регион, сохранность числа ячеек, положительные объёмы и отсутствие внутренней разделяющей стенки. Ноль отдельных интерфейсов в режиме Fuse ожидаем.
3. Проверить все четыре внешних зазора: они не должны называться стержнями. Проверить `rod_R<id>` по исходной геометрии, а не только по площади.
4. Включить каждую пару индивидуальных сечений на одном Z поочерёдно: каждое должно покрывать только свой подканал; сумма площадей должна соответствовать общему сечению. Проверить два осевых зонда и выбранные номера подканалов.
5. Проверить наличие отчётов и мониторов, отсутствие `[!]`. Настроить реальные условия входа/выхода и выполнить отдельную проверку стационарного массового/теплового баланса на задаче с известными расходом и тепловой мощностью. Для адиабатических стенок ожидается Q_walls≈0; для нагреваемых — проверить знак Q_walls и согласование с изменением потока энтальпии.
6. Повторить экспорт в Internal Interface: два региона, корректный интерфейс и сечения по отдельным регионам.

Автоматические тесты проверяют геометрические метаданные, восстановление ячеек исходных подканалов масками, генерацию макроса, ограничения GUI и отказоустойчивость создания отчётов. При наличии JDK выполняется реальный Java-классификатор и проверка синтаксиса полного макроса. Это не компиляция с библиотеками STAR-CCM+ и не выполнение новых Threshold/энергетических API в решателе; такая приёмка остаётся обязательной.

## Короткие имена и сечения общих зазоров

В именах поперечных сечений указывается физическая высота в миллиметрах без лишних нулей: например, `Section_Global_Z_25mm`. Число в имени — подпись; координата плоскости передаётся отдельно с полной точностью. Ссылки отчётов используют то же имя.

Для Fuse доступен флажок «Продольные сечения зазоров между исходными подканалами». На каждую пару соседей создаётся `Gap_SubA_SubB` — вертикальная плоскость через общую сторону исходных треугольников. Её нормаль направлена от подканала A к B. В качестве входной области используется только Domain подканала A: это ограничивает сечение нужным зазором и не создаёт две совпадающие поверхности с обеих сторон. Остальные коллинеарные зазоры большой сборки в эту область не входят. Новых физических стенок или интерфейсов не создаётся.

При включённых отчётах создаётся `MassFlow_Gap_SubA_SubB` с монитором. Положительный знак соответствует направлению нормали A→B; знак нужно проверить на контрольном течении. Это отчёт по производной поверхности, а не по Boundary Interface.

## Гистограммы и скалярные сцены качества

На вкладке «Мониторы и параметры» доступны независимые опции:

- Гистограммы с отчётами min/max: `Quality_Histogram_<metric>` с суффиксами порогов, перечисленными ниже. Источник — все объёмные регионы импортированной сборки, а не только внешние стенки. По оси X — значение метрики STAR, по оси Y — частота (число ячеек), без взвешивания объёмом. Число интервалов задаётся в GUI, по умолчанию 50; диапазон данных автоматический, чтобы не исключать значения вне ожидаемых границ.
- Отчёты `Quality_Min_<metric>` и `Quality_Max_<metric>` с мониторами используют те же регионы. Они создаются и при выборе только скалярных сцен. Ошибка создания гистограммы не должна блокировать отчёты min/max или сцену другой метрики.
- Сцены `Quality_<metric>` показывают метрику на среднем поперечном сечении. Назначены поле, входное сечение и представление Volume Mesh; используется Native Fill без сглаживания по узлам. При отсутствии общего среднего сечения создаётся одно `Quality_Section_Z_...mm`. Готовое общее сечение переиспользуется. Если сечение не создано, макрос сообщает ошибку вместо пустой сцены.

Диаграммы описывают всю сетку, а скалярная сцена среднего сечения — только один срез. Хороший вид одного среза не исключает плохих ячеек в других местах. Диагностика объёмов и общая оценка качества в STAR по-прежнему необходимы. Для Cell Quality, Face Validity и Volume Change малые значения требуют внимания; для Skewness Angle — большие. Порог пригодности зависит от задачи: гистограммы и min/max не выдают автоматического разрешения на расчёт. Проверьте диапазон легенды при осмотре сцены.

Гистограммы используют API Cartesian2DPlot/HistogramDataSeriesConfig, сверенный с исходным кодом [MacroUtils для STAR-CCM+ 2602](https://github.com/frkasper/MacroUtils/blob/v2602-0320/macroutils/src/macroutils/creator/CreatePlot.java) и [настройкой binning](https://github.com/frkasper/MacroUtils/blob/v2602-0320/macroutils/src/macroutils/setter/SetPlots.java). Библиотека MacroUtils не подключается к проекту. Новые функции предназначены для проверки в 2602; совместимость этого API со старыми версиями не подтверждена.

Пользователь подтвердил успешный запуск базового исправления Fuse (`56f3dd3`) в 2602. Короткие имена, сечения зазоров и новые объекты контроля качества добавлены после этой проверки и требуют повторного запуска нового макроса. В новой тестовой симуляции проверить:

1. У двух соседних подканалов есть одно непустое `Gap_Sub1_Sub2`; его площадь соответствует ширине зазора × высоте. Нормаль направлена от Sub1 к Sub2. Между регионами не возникла новая стенка.
2. На вкладке Plots присутствуют четыре гистограммы; сумма частот по всем регионам соответствует числу импортированных ячеек. Изменение числа интервалов меняет разбиение, но не число учитываемых ячеек.
3. Min/max согласуются с диагностикой STAR для тех же определений метрик. Сцены имеют назначенные поля, непустое сечение, видимую заливку и подходящую легенду. Наличие пустых или неподдерживаемых данных должно сопровождаться `[!]`.
4. Отключение опций в диалоге отключает именно соответствующие объекты. На исходном режиме Internal Interface новые опции качества также проверяются, а Fuse-сечения зазоров недоступны.

Пороги диагностики также включены в имена гистограмм:

| Имя | Выделяемый подписью диапазон плохих значений |
|---|---|
| `Quality_Histogram_CellQuality__bad_lt_1e-5` | Cell Quality < 1e-5 |
| `Quality_Histogram_FaceValidity__bad_lt_1` | Face Validity < 1 |
| `Quality_Histogram_VolumeChange__bad_le_0.01` | Volume Change ≤ 0,01 |
| `Quality_Histogram_SkewnessAngle__bad_gt_85deg` | Skewness Angle > 85° |

`lt`, `le`, `gt` обозначают `<`, `≤`, `>`. В заголовке диаграммы условие записано обычным математическим знаком. В имени объекта нет символов `<`/`>`, мешающих последующему экспорту в имена файлов Windows. Пороги в подписях — ориентиры диагностики; они не фильтруют данные и не меняют автоматический диапазон или число интервалов. В гистограмме остаются все ячейки.

## Профили экспорта

Внизу диалога доступны «Сохранить профиль экспорта…» и «Загрузить профиль экспорта…». JSON сохраняет топологию, физические опции, параметры сечений/зондов, выбранные номера подканалов, качество и число интервалов, создание отчётов, Threshold, дополнительных полей, групп и сводки. Файл сетки, физические свойства среды и состояние решателя в профиль не входят.

Формат `meshBuilder-star-export`, версия 1. Перед применением проверяются все типы, диапазоны, совместимость Fuse/60°, доступность выбранных номеров подканалов и версия файла. Ошибка не должна частично изменить GUI. Чужой JSON проекта сетки не является профилем экспорта. Если профиль содержит подканал, отсутствующий в текущей сетке, он отклоняется; выбор не исправляется молча.

## Владение объектами и повторный запуск

Новая версия ставит собственным объектам тег `meshBuilder.Managed`, а регионам — подпись геометрии/топологии `meshBuilder.Mesh.<hash>` и номер источника. Входы, выходы, стержни и внешние зазоры получают теги ролей, поэтому их ручное переименование не мешает следующему запуску.

Первый запуск этой версии должен выполняться в новой пустой симуляции. Прежние симуляции из макросов без тегов не присваиваются новому макросу автоматически. При включённом импорте непустая симуляция без подходящей подписи отклоняется до импорта. Режим отключённого импорта допускает первоначальную сборку уже импортированных Zone N по прежнему сценарию; это не режим обновления произвольных готовых регионов.

При следующем запуске того же экспорта:

- Проверяются подпись, число управляемых регионов и фактическое число ячеек. Другая сетка или топология требуют новой симуляции.
- Импорт, слияние, классификация границ, установка физики и исходных глобальных параметров пропускаются. Ручные типы и значения граничных условий не переназначаются. Физические опции профиля применяются при первом импорте; смена модели в профиле не заменит вручную настроенную физику при повторном запуске.
- Совпадающие по имени объекты анализа обновляются только при наличии тега владельца и подходящего типа. При совпадении с пользовательским объектом выводится ошибка; он не перезаписывается.
- Плоскости, зонды, маски, Threshold, отчёты и гистограммы переиспользуются. Изменение числа интервалов обновляет binning существующей диаграммы. Монитор, уже связанный с отчётом, не дублируется. Пользовательские теги сохраняются.
- Отключённые опции перестают создавать/обновлять соответствующие объекты, но ранее созданные объекты не удаляются. Аналогично старые положения сечений остаются при уменьшении их количества. Это намеренно сохраняет возможные ручные ссылки на них. Не переименовывайте управляемые объекты анализа, если хотите обновлять их по прежнему имени.

Подпись проверяет соответствие новому экспорту и счётчикам, но не вычисляет контрольную сумму координат внутри STAR. Ручное перемещение узлов при неизменном числе ячеек таким способом не обнаруживается. После ручной модификации сетки используйте новую симуляцию/новый экспорт.

Группы `meshBuilder_*` создаются по назначению объектов: Quality, Gaps, Subchannels, Sections, Reports, Monitors, Plots, Scenes, FieldFunctions, Parameters. Пользовательские объекты не добавляются в группы макроса. Если API группировки не поддерживается, появляется `[!]`, а владение тегами сохраняется.

## Плохие ячейки: маски, количество и доля

Опция «Выделять плохие ячейки» создаёт бинарные функции `MB_Bad_CellQuality`, `MB_Bad_FaceValidity`, `MB_Bad_VolumeChange`, `MB_Bad_SkewnessAngle`: 1 — условие плохой ячейки выполнено, 0 — нет. Пороги совпадают с подписями гистограмм. Для каждой создаются `Quality_BadCells_<criterion>` (Threshold), `Quality_BadCount_<criterion>` и `Quality_BadPercent_<criterion>` с мониторами. Знаменатель доли — `Quality_TotalCellCount` по всем регионам текущего экспорта.

`MB_BadAnyQuality`, `Quality_BadCells_Any`, `Quality_BadCount_Any` и `Quality_BadPercent_Any` объединяют четыре критерия через логическое ИЛИ. Ячейка, нарушающая несколько критериев, в общем количестве учитывается один раз. Если хотя бы один критерий не создан, объединение не выдаётся за полную проверку: выводится предупреждение. Дополнительно создаётся проверка `NonPositiveVolume` по нулевому/отрицательному объёму. Хорошие метрики не отменяют проверку разрешения градиентов, y+ и сеточной сходимости.

На хорошей сетке Threshold может быть пустым — это ожидаемый результат. Чтобы увидеть проблемные ячейки, добавьте соответствующий `Quality_BadCells_*` в сцену. Количество и процент проверяйте после вычисления отчётов/инициализации данных STAR, а не только по наличию объекта в дереве.

## Функции поля

Все функции сохраняются в Tools → Field Functions; служебные координатные поля после классификации больше не удаляются.

| Функция | Смысл |
|---|---|
| `MB_One` | Константа 1 для интегралов площади |
| `MB_X`, `MB_Y`, `MB_Z` | Компоненты координаты центроида, размерность длины |
| `MB_ZFraction` | Координата Z, делённая на высоту экспорта: безразмерная величина |
| `MB_Speed` | Модуль скорости, м/с |
| `MB_MassFluxMagnitude` | Плотность × модуль скорости, кг/(м²·с); это модуль, не знаковый расход через поверхность |
| `MB_SubchannelMask_N` | Геометрическая маска исходного подканала в Fuse |
| `MB_CellQuality`, `MB_FaceValidity`, `MB_VolumeChange`, `MB_SkewnessAngle` | Именованные ссылки на доступные нативные поля качества STAR |
| `MB_Bad_*`, `MB_BadAnyQuality` | Бинарные признаки плохих ячеек |
| `MB_MassBalanceSigned` | Знаковая сумма суммарных расходов входа и выхода |
| `MB_EnergyBalanceSigned` | Знаковая сумма потоков энтальпии минус тепловая мощность стенок при включённой энергии |

Дополнительные функции можно отключить в GUI. Обязательные поля, нужные выбранным Threshold/маскам и классификации, при этом остаются. Поля скорости и массового потока зависят от выбранной физики; при недоступной зависимости появляется предупреждение. Балансовые поля зависят от созданных отчётов и наследуют ограничения принятой модели баланса.

## Итоговая сводка

Опция сводки выводит результаты управляемых отчётов в Output и записывает UTF-8 CSV `meshBuilder_audit_*.csv` в каталог, разрешённый `resolvePath(".")` (при сохранённой тестовой симуляции — её рабочая папка). Каждый запуск создаёт новый файл, не затирая предыдущий. В нём подпись экспорта, запрошенные настройки, версия STAR, ожидаемое число ячеек, число регионов и управляемых объектов, значения отчётов с единицами и сообщения об ошибках. Недоступные/нечисловые значения сопровождаются предупреждениями; они не считаются успешной проверкой.

Сводка не запускает CFD-решение. Нулевые расходы при границах Wall и неинициализированном поле не доказывают корректность баланса. Исходные типы границ по-прежнему задаёт пользователь.

## Дополнительная приёмка этой версии в 2602

1. Сохранить профиль, закрыть диалог, открыть заново и загрузить профиль: настройки должны восстановиться; несовместимый профиль должен оставить текущие настройки без изменений.
2. Выполнить новый макрос в новой симуляции. Проверить группы, поля, Threshold, количество/долю плохих ячеек, CSV и все `[!]`.
3. Задать собственные условия входа/выхода и сохранить их значения. Повторить тот же макрос: число физических ячеек/регионов и объектов анализа не должно расти, условия и физика должны сохраниться, CSV должен быть новым.
4. Изменить только число интервалов гистограммы и заново сгенерировать макрос для той же сетки: диаграмма должна обновиться без дублирования.
5. В отдельной копии создать нетегированный объект с требуемым именем: макрос должен сообщить конфликт, не менять его. Другая геометрия/топология должна отклоняться до нового импорта.

Эти новые функции требуют повторной проверки с библиотеками STAR-CCM+ 2602. Автотесты с тестовыми заменами STAR API не являются такой проверкой.

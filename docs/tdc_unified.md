# TDC в общем окне экспорта STAR-CCM+ 2602

Вкладка 7 использует общие настройки восьми вкладок. Она не меняет геометрию,
свойства, нагрев или периодические пары скрытым эталонным режимом. Нет привязки
к S18/S22, длине 300 мм или числу три. BMBC и оценка погрешности не выполняются.

## Подготовка

1. Полная конформная сетка. Fuse или отдельные регионы. Выбор A/B относится к
   номерам исходных подканалов экспорта; отображение на оригинальные геометрические
   объекты сохраняется в `TDC_export.json`.
2. Нестационарный расчёт (RST или Hybrid SRH–SST), постоянные свойства, энергия,
   без гравитации. Тепловые потоки каждой группы ТВЭЛ задаются в «Физике».
   НК/ИК остаются адиабатическими стенками. Неравномерные по группам q допустимы.
3. В «Сетке» явно задать Fully Developed + Periodic вход–выход и расчётный расход.
   При ручном расходе проверяется совпадение с аналитическим G=ρU_b калькулятора y+.
   Для отдельных регионов задаётся своя осевая пара каждому подканалу.
4. Боковые периодические пары задаются тем же редактором. Незаданные внешние
   стенки должны оставаться адиабатическими; Symmetry допустима.
5. В «Производных частях» число сечений определяет обязательные сечения TDC:
   минимум 3, максимум 100 в текущем общем виджете. Внутренние плоскости общей серии переиспользуются. Вход/выход для потоковых балансов выделяются на действительных
   дочерних InterfaceBoundary, с маской источника при Fuse.
6. В «Отчётах» можно выбрать дополнительную гидравлику, тепловые отчёты и Darcy.
   В «Среднее по времени» выбрать поля, разгон, блоки и окончание. TDC больше
   не отключает индивидуальный выбор полей.

Выберите A по исходным номерам стержней, диаметрам, типам ТВЭЛ/НК/ИК и назначенному
нагреву; горячее состояние затем проверяется по температуре. Выберите B и **один
целевой зазор**. Остальные боковые стороны показаны отдельно:

| Условие / поверхность | Учёт мощности наружу из подканала |
| --- | --- |
| Symmetry, адиабатическая Wall | Ноль по назначенному условию |
| Действительная сторона Internal/Periodic | Интеграл чувствительной конвективной энергии плюс BoundaryConductionHeatFlux |
| Другой внутренний разрез Fuse | Реконструкция по полям при скалярном замыкании либо готовый знаковый отчёт мощности |
| Не измерено | Экспорт TDC заблокирован: остаётся второй неизвестный перенос |

Каждый подканал имеет своё направление наружу. Отчёт пользователя должен выдавать
полную мощность в W с этим знаком; существующий отчёт не изменяется. Измеренный
обмен с третьим соседом допустим. Равенство площадей разных зазоров и подтверждение
эквивалентности не требуются. Геометрическая совместимость двух сторон конкретной
периодической пары по-прежнему проверяется общим редактором.

Предпросмотр выделяет целевой обмен. Для узкого внутреннего зазора Fuse при одной
боковой периодической паре и двух Symmetry весь остаток относится именно к узкому
зазору **после вычитания измеренной мощности периодических сторон**.

Группировка стенок по физическому стержню при Fuse поддерживается: для нагрева
каждого подканала выделяется его часть общей стенки маской. Сток рассчитывается
по суммарной мощности всех нагретых стенок, без двойного учёта общих границ.

## Математика и знаки

Положительные Q_A и ΔT соответствуют A → B. Нагрев W_A положителен в жидкость.
Объёмный источник S_A имеет физический знак: сток отрицателен.

```
Q_A(t) без накопления = W_A(t) + S_A(t) − [F_out,A(t) − F_in,A(t)]
H_A(t) = ∫_V ρ Cp (T − T_init) dV
Q̄_A = mean(Q_A без накопления) − mean(OtherOut_A) − [H_A(t1) − H_A(t0)]/(t1 − t0)
Q̄_B = −{mean(Q_B без накопления) − mean(OtherOut_B) − [H_B(t1) − H_B(t0)]/(t1 − t0)}
```

OtherOut — сумма мощностей через все остальные открытые боковые стороны,
положительная наружу. F — поток чувствительной энергии. Осевые диффузионные потоки должны
компенсироваться на периодических копиях. Баланс не включает дополнительную
механическую работу или произвольно включённые источники вне этой постановки.

Компенсационный сток общий для модели:

```
q_v = −sum(q_i × измеренная площадь нагреваемой границы_i) / V_model
```

Для каждой группы q_i — постоянная скалярная функция поля из общей настройки.
Сток назначается всем регионам вторым макросом до инициализации. Его интеграл
по каждому исходному подканалу измеряется отдельным VolumeIntegralReport.

На каждом шаге и сечении:

```
T_b(z,t) = ∫ ρ u_z T dS / ∫ ρ u_z dS
ΔT_L(t) = [0.5 ΔT(z0,t) + sum_interior ΔT(z_k,t) + 0.5 ΔT(zN,t)] / (N_sections−1)
G_ref = ρ U_b  (общий аналитический, постоянный)
TDC = Q̄_A / [A_exchange × Cp × G_ref × mean(ΔT_L)]
```

Это **безразмерный эффективный коэффициент обмена**. Молекулярная и средняя
конвективная составляющие не отделены от турбулентной. Чисто турбулентный
коэффициент и диффузивность в м²/с этим результатом не объявляются.
Молекулярная поправка заблокирована до проверки полного диффузионного переноса
на всех поверхностях; флажок не может экспортировать непроверенную формулу.

Принятие результата требует:

- |mean(ΔT_L)| не меньше заданного минимального контраста;
- Q̄_A и mean(ΔT_L) имеют одинаковый знак;
- |Q̄_A − Q̄_B| / max(|Q̄_A|,|Q̄_B|) не превышает допуска баланса;
- измеренные парные стороны Internal/Periodic имеют противоположные средние мощности в пределах допуска;
- все обязательные мгновенные значения конечны и время строго возрастает.

A может быть горячим или холодным: при перестановке A/B оба знака меняются,
коэффициент сохраняется. Это проверка постановки и баланса, не критерий
статистической сходимости. При ResultValid=0 исходные данные и средние сохраняются,
но текущий TDC отсутствует в CSV; прежний скалярный TDC переименовывается как
Unavailable, чтобы не выглядеть актуальным результатом.

## Как накапливаются средние

- Скаляры: интеграл трапециями по фактическому физическому времени / длительность.
  Усредняются мгновенные отчёты, а не история уже накопленного среднего.
- Общие поля: штатные FieldMeanMonitor, один отсчёт на завершённый шаг, постоянный dt.
  Отдельные компоненты скорости и напряжения используют общие настройки вкладки 5.
  Поля включены только при сборе серии; старые серии не сбрасываются.
- Блоки: каждый имеет своё окно, запас энергии на своих концах и результат отношения
  средних. На стыках сырой CSV повторяет конечную точку для интегрирования блока,
  но общее окно пропускает этот повторный отсчёт.
- Итоговый TDC вычисляется заново по общей истории. Это не среднее блочных TDC.
- При выключенных блоках собирается одно окно от начала серии до окончания.
- Разгон и блоки округляются вверх до целого числа шагов. Ручное окончание не
  допускается ниже полученного суммарного бюджета; дополнительное время попадает
  в последний блок.

Выбранные обычные отчёты расходов, балансов, Re, Darcy, температур и тепловых
мощностей также получают скалярные средние. Отсутствие мгновенного монитора
не мешает усреднить отчёт; лишние мониторы расходов специально не создаются.

## Запуск и файлы

Комплект: XYZ, `setup_starccm_subchannels.java`, `TDC_Hybrid.java`,
`TDC_export.json`, `TDC_START.txt`. Анализатора BMBC нет. Файлы публикуются
с откатом при ошибке; отмена до публикации сохраняет существующий комплект.

1. Новый пустой .sim → импортный макрос. Он назначает общие физику, нагрев и пары.
2. Второй макрос, `TDC_Action=0`: отчёты и сток. Никакого запуска/инициализации.
3. Проверить условия, знаки, преобразования периодичности; Initialize вручную.
4. `TDC_Action=1`: совместный разгон до абсолютного заданного времени.
5. После проверки установления: `TDC_AllowStatistics=1`, `TDC_Action=3` — новая серия.
6. `TDC_Action=4`: запустить запланированный сбор. `5` — повторно выгрузить, `6` — статус.

Решатель продвигается только явными действиями 1/4. Action автоматически
возвращается в 0; данные не переинициализируются. В активной серии нельзя менять
dt, физику, q, источник и назначения BC или выполнять шаги вне контроллера.
Настройки/определения проверяются при продолжении. Незавершённый `.partial.csv`
не принимается за готовый блок. После прерванного блока требуется новая серия.

В каталоге серии: `block_NNNNN.csv` (сырые сигналы), `blocks.csv`, `summary.csv`,
`cumulative.csv`, `units.csv`, `configuration.txt`. Колонка time_stddev — разброс
сигнала, не погрешность среднего. Публикуются отчёты Mean_/LastBlock_/
Cumulative_. Для накопленных ΔT, обмена, баланса, ResultValid и TDC создаются
мониторы и, при доступном API, нативные графики. Монитор снимает обновлённый
скаляр на следующем событии решателя; точные текущие времена лежат в cumulative.csv.
Если API графиков недоступен, выдаётся явное предупреждение, CSV сохраняется.

## Проверки и пределы

Python/Qt offscreen и исполнение Java-ядра проверяют знаки, накопление,
отсутствие двойного отсчёта, отношение средних, охранные условия, выбор геометрии,
профили и публикацию. Компиляция Java против явных контрактов — **не Siemens SDK**.
В STAR 2602 ещё необходимо проверить отчёты на масках интерфейсов, полевые
средние/их паузу, единицы, нативные графики и запуск на небольшой тестовой сетке.

Старые `tmc_reference` и шаблон в `tmc/` сохранены для воспроизводимости прежнего
эталона и его тестов. Новый UI использует `export_mode=tdc` и `workflow.tdc_settings`.

Старый эталонный профиль можно читать/сохранять прежним контрактом, но загрузка
его в новый GUI отклоняется до изменения виджетов с объяснением: автоматическая
подстановка прежних трёх зазоров и скрытых q была бы физически неоднозначной.
Исходный файл не изменяется; пары/нагрев нужно явно задать в общих вкладках.

## Проверка боковых измерений

На настоящей InterfaceBoundary требуется проверить, что BoundaryConductionHeatFlux
доступна и корректно учитывает молекулярную и моделируемую турбулентную диффузию.
Отсутствие поля или неконечное значение не заменяется нулём. Нулевое значение само
по себе не доказывает правильность назначения. Конвекция используется в той же
системе отсчёта энергии, что и объёмный баланс: ρ Cp (T−T_init) u_n.

На внутренней плоскости Fuse граничный тепловой поток не используется. Опциональная
реконструкция равна −EffectiveConductivity × grad(T)·n; она допустима только при
соответствующем скалярном замыкании и не является точным дискретным потоком решателя.
Нужно подтвердить этот выбор и проверить баланс на тестовой модели.

Для каждого открытого пути создаётся также MassFlowOut и его среднее по времени.
При заметном среднем поперечном расходе результат включает направленный перенос;
приписывать его только турбулентному перемешиванию нельзя. При ненулевом расходе
через целевой зазор энергетическая мощность с фиксированным T_init зависит от
начала отсчёта энтальпии; для выделения чистого перемешивания нужна отдельная
декомпозиция, которой эта настройка не выполняет.

Основание для определения поля: Siemens, [Heat Transfer Field Functions Reference](https://www.topcfd.cn/Ebook/STARCCMP/GUID-973F49CA-1A5E-4B8C-9A2C-609C5D76C862.html).
Это не заменяет проверку API и отчётов в вашей версии STAR 2602.

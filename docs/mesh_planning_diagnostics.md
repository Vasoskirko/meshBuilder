# Оценка размера, диагностика и сравнение сеток

## До построения

На вкладке сетки нажмите **Оценить размер и память…**. Результат появится в журнале. Оценка не строит полную сетку и не делает существующую сетку недействительной.

Для заданного числа ячеек прогноз количества точный при условии успешного построения. Для автоматических законов выводится диапазон: верхняя граница определяется заданным ограничением числа ячеек и не означает ожидаемый расход памяти. После построения пригодного пристеночного слоя оценка ядра уточняется по оставшейся длине лучей.

Число узлов и объём координат учитывают повторяющиеся узлы на стыках блоков. Диапазон размера относится к ASCII Plot3D XYZ. Оценка памяти проверки качества приблизительная: она не гарантирует пиковый расход и не включает GUI, библиотеки и другие процессы. Прогноз не подтверждает геометрическую допустимость сетки.

## Поиск ячеек

Над рисунком выберите критерий, задайте порог и нажмите **Найти ячейки**:

- **Якобиан формы**: значения ниже порога; по умолчанию 0,2.
- **Отклонение углов от 90°**: значения выше порога; по умолчанию 30°.
- **Пропорции в сечении**: отношение большего размера к меньшему в плоскости сечения; по умолчанию выше 5.
- **Перепад объёмов внутри блока**: максимальное отношение объёмов соседних ячеек; по умолчанию выше 2. Стыки разных блоков здесь не проверяются.

Недопустимые ячейки включаются независимо от выбранного порога. В журнале приводится полный подсчёт, но для сохранения отзывчивости отображается не более 2000 худших ячеек. Нажатие на подсвеченную ячейку показывает блок, индексы, номер от стенки и значения критериев. Флажок **Подсветка** меняет только отображение.

Диагностика использует один осевой слой: это соответствует текущему прямому равномерному вытягиванию сетки. Число отмеченных ячеек полного объёма учитывает nz. Угловой критерий здесь определён через отклонение углов и не объявляется эквивалентом поля STAR-CCM+. Вытянутые пристеночные ячейки могут быть намеренными; пороги служат для поиска, а не автоматического заключения о пригодности для CFD. Изменение параметров сбрасывает результаты диагностики.

## Варианты A и B

В меню **Варианты** запомните текущую сетку как A. Затем измените параметры и постройте B. Там же доступны сравнение показателей и удаление A. Экспорт использует только актуальную сетку B.

Флажок **A — серый** накладывает старые линии на новую сетку при одинаковой применённой геометрии и выборке подканалов. При другой геометрии доступно числовое сравнение, но наложение скрывается. Показатель пропорций в таблице сравнения учитывает три направления; критерий подсветки пропорций — только сечение.

A удерживается в памяти до удаления или открытия проекта; в журнале указывается минимальный дополнительный объём координат. Это временное сравнение: A и подсветка не записываются в JSON проекта.

## Откуда берутся параметры

Под выбором области редактирования показан источник: общие параметры, собственные параметры шаблона или собственные параметры блока. Приоритет: блок → шаблон → общие параметры. Переключение области без редактирования не инвалидирует сетку.

Z и nz общие. Число узлов по дуге ni, распределение по нормали, пристеночный слой и ядро могут переопределяться для шаблонов и отдельных блоков. Различие параметров может приводить к неконформным стыкам — см. [локальное редактирование](local_block_settings.md). Незавершённые допустимые значения активных полей применяются перед оценкой, сохранением проекта и заполнением ядра; изменение параметров слоя требует его перестроения.

## Скорость построения

Поиск стыков использует пространственный индекс концов граней вместо полного перебора пар. Затем по-прежнему проверяются все узлы кандидатов, включая обратный порядок и несовместимое разбиение. Математика построения ячеек не меняется. Прогресс обновляется между подканалами; там же обрабатывается отмена.

Для воспроизводимого замера генератора запустите `python tools/benchmark_bundle_build.py`. На тестовой машине (Python 3.12, 24 подканала, 144 блока, ni=80, nj=100, nz=20) медиана трёх запусков снизилась с 8,400 до 1,172 с. Массивы координат, список интерфейсов и диагностика совпали побитово. Это 22 524 480 эквивалентных 3D-ячеек; сам генератор хранит сечения, а не полный объёмный массив.

Это не замер всей операции в GUI: последующие проверка качества, отрисовка и экспорт не включены. Они по-прежнему требуют времени и памяти; ускорение на другом компьютере и другой геометрии может отличаться. Порогов времени в CI нет: регрессионные тесты проверяют полноту поиска и равенство результатов с полным перебором.

### Проверка качества и память

Проверка качества в конструкторе теперь создаёт и обрабатывает объёмные координаты по одному блоку, вместо хранения объёмных массивов всей сборки. Для сопоставления стыков сохраняются копии только нужных граничных слоёв. Геометрия граней, центры и объёмы вычисляются один раз для нескольких критериев; длины рёбер также переиспользуются. Формулы критериев, подсчёты, координаты худших ячеек и проверки стыков сохранены.

Повторяемость осевых слоёв пока не используется для сокращения проверки: проверяются все ячейки и внутренние грани, включая осевые. Это сохраняет прежние результаты без предположений о равенстве значений с учётом округления.

Для отдельного замера: `python tools/benchmark_bundle_quality.py`. Размер примера задаётся через `--ni`, `--nj`, `--nz`, JSON отчёта сохраняется через `--report файл.json`. Для сравнения с прежней реализацией можно передать её локальный файл `mesh_quality.py` через `--reference путь`. Время включает создание объёмных координат и проверку, но исключает построение сечений, отрисовку и экспорт. Peak RSS — пик всего процесса, включая библиотеки, а не только массивы сетки; на Windows этот показатель инструментом не измеряется.

Ограничение: один очень большой блок всё ещё требует памяти пропорционально его полному объёму. Граничные слои стыков также занимают память. Отмена обрабатывается между блоками; разбиение отдельного блока на порции остаётся следующим возможным улучшением. Общий анализатор файлов без явной топологии сохраняет прежний режим загрузки и поиска стыков.

Контрольный замер Linux/Python 3.12: 24 подканала, 144 блока, ni=40, nj=50, nz=12, всего 3 302 208 ячеек. В двух отдельных процессах с одинаковыми импортами: прежняя проверка — 9,448 с и 205,80 МиБ peak RSS; новая — 7,139 с и 120,89 МиБ. Полные JSON-отчёты совпали. Это одиночный сравнительный замер, а не гарантированная скорость на других компьютерах.

Изменение общего ni меняет значение по умолчанию; собственные ni шаблонов и блоков сохраняются. Общими для всех областей остаются Z и nz. Кнопка сброса явно указывает область действия: выбранный блок, выбранный шаблон либо все переопределения в области «Ко всем блокам». Последний вариант сохраняет общие параметры и удаляет локальные настройки шаблонов/блоков.

# Единое окно экспорта STAR-CCM+ 2602

Окно конструктора теперь содержит семь вкладок. Отдельного режима с другой формой
TMC нет; методика называется **TDC** и включается внутри общей подготовки расчёта.

## Что работает

1. **Сетка.** Оценка размера текущего ASCII Plot3D без разворачивания 3D-массивов;
   интерфейсы или Fuse между подканалами; сохранение секторов и поддерживаемая
   группировка стенок. При отдельных регионах объединение по физическому стержню
   недоступно. После Fuse исходные объёмные области создаются обязательно.
2. **Физика.** RST или HYBRID · SRH / SST; значения свойств из калькулятора y+
   доступны для проверки и изменения. IAPWS EOS допускает явно заданные постоянные
   вязкость и теплопроводность либо независимый выбор их методов IAPWS. Энергия при IAPWS обязательна. Настраиваются
   Reference Pressure, Initial Pressure, Initial Temperature и начальная скорость
   (нулевая, осевая из калькулятора либо VelocitySeed). Десятичная точка и запятая равноправны.
3. **Геометрии и отчёты.** Исходные подканалы, общие балансы, отдельные и общие
   сечения, осевые линии, список всех соседних зазоров. Автоматические ключевые
   общие плоскости отключены: общий и индивидуальный наборы выбираются явно.
   Выбранные группы отчётов используют существующий анализатор макроса.
   Автоматически создаются предложенные функции VelocitySeed; назначение
   возмущений начальным условием доступно в «Физике → Скорость».
4. **Статистика.** Постоянный `${timeStep}`; Second Order; SIMPLEC; Maximum Inner
   Iterations (по умолчанию 5); Maximum Steps выключается; Maximum Physical Time
   получает конец отрезка совместного разгона. Вызовы API выполняются с проверкой:
   отсутствие обязательного метода останавливает макрос с ошибкой, а не запускает
   расчёт с иными настройками. Повторный импорт сохраняет существующее решение.
   Для общего HYBRID средние поля имеют явно задаваемый начальный шаг; автоматическое
   управление разгоном/блоками пока доступно только контроллеру эталона TDC.
5. **Качество.** Главный чекбокс выключен по умолчанию. Пороги доступны для изменения;
   выключенный этап не создаёт сцены, гистограммы, bad-cell наборы и отчёты качества.
   Неположительный объём входит в включённый этап. Обязательные проверки актуальности,
   полноты и конформности экспорта этим чекбоксом не отключаются.
6. **TDC.** Эталон S18/S22, два подканала, L=300 мм, P=11,64 мм, D=9,1 мм.
   Общие свойства и время берутся из тех же полей, что у обычного экспорта.
   Пользователь явно выбирает Fuse, SRH/SST, постоянные свойства, энергию,
   исходные rod-секторы и подтверждает три эквивалентных зазора.
   Несогласованные настройки блокируют сохранение, не меняются автоматически.
7. **Итог.** Сводка и управление вычислением физических отчётов. Автоматическая
   инициализация недоступна: для общего экспорта границы остаются wall, а для TDC
   периодичность назначается вторым макросом. Инициализируйте вручную после настройки.

Профили и проекты хранят вложенный словарь `workflow` версии 1. Старые профили без
него загружаются с миграцией признака качества и настроек прежнего TMC. Имена
внутренних ключей `tmc_settings`/`tmc_reference` сохранены для совместимости формата.
В новом комплекте файлы, Java-класс, параметры/отчёты и анализатор именуются TDC.

## Порядок TDC

1. Открыть/построить актуальную полную конформную эталонную сетку.
2. Настроить общую физику; включить TDC, проверить нагрев, расход и допущение трёх зазоров.
3. Сохранить комплект; выполнять сначала `setup_starccm_subchannels.java`,
   затем `TDC_Hybrid.java` с Action=0 на копии симуляции.
4. Проверить интерфейсы, свойства, знаки источника и сообщения ошибок; Initialize.
5. Action=1 — совместный гидродинамический и тепловой разгон без статистики.
   Action=2 также продолжает разгон с включённой энергией.
6. После установления явно разрешить статистику и Action=3 создать новую серию.
   Action=4 добавляет блоки; Action=5 выгружает; Action=6 показывает состояние.
   После каждого действия Action сбрасывается, решение не переинициализируется.

Контроллер связывает свой параметр шага с `${timeStep}`, обновляет Maximum Physical
Time перед очередным отрезком и отключает Maximum Steps. Блоковые скалярные средние
учитывают фактическое время; средние поля серии не сбрасываются на каждом блоке.
Boundary Heat Flux включён в опциональный набор средних полей контроллера.
`TDC_analyse_series.py` читает новые TDC-колонки CSV, а не прежние TMC-имена.

Температура для TDC — среднее по времени мгновенных среднемассовых температур,
с согласованным усреднением вдоль длины. `Mean of Temperature` не подменяет
мгновенную температуру в балансе. Коэффициент по принятой формуле статьи
безразмерный; это не отдельная размерная диффузивность в м²/с.

## Ограничения — показаны в окне

- Неконформный CFD-экспорт пока запрещён. Произвольное создание внутренних
  неконформных интерфейсов требует проверки импортёра и API STAR.
- Общее правило группировки сохраняет ТВЭЛ/НК/ИК раздельными. Независимый выбор правила для каждого типа и объединение всех rods пока не реализованы.
- Общий редактор поддерживает Wall, Symmetry, Mass Flow Inlet, Pressure Outlet, Internal, Internal + Periodic и Fully Developed + Periodic. Для входной турбулентности, обратного потока и явной настройки оси/угла периодического преобразования отдельных полей пока нет.
- Выбор стороны периодического интерфейса для каждого общего отчёта ещё не внедрён;
  обычный анализ использует измерительные сечения.
- Общие отчёты трения используют средний модуль напряжения. Они не являются
  осевой силой трения или полным КГС. Расширение на все физические типы стенок
  и осевую силу ещё требуется.
- Переменные транспортные методы IAPWS назначаются по записи команд 2602.
  Их фактическую работу нужно проверить в STAR-CCM+; локальные контракты не заменяют Siemens SDK.
- Для произвольной модели блоковый контроллер и отдельная настройка каждого
  монитора/графика пока не реализованы. Параметры блоков сохраняются, но применяются
  автоматически только для эталона TDC.
- Вызовы реальной STAR-CCM+ 2602 не проверялись в среде разработки. Java-контракты,
  исполняемый адаптер решателя и численное ядро тестируются без Siemens SDK.

Новые файлы сначала записываются временно. Отмена до публикации сохраняет старый
комплект; при ошибке замены выполняется откат. Если восстановление само не удаётся,
резервная копия сохраняется, а путь включается в сообщение ошибки.

## Проверки этой интеграции

Полный offscreen-прогон после компактного оформления: 226 тестов, OK (71,297 с). Дополнительно выполнен целевой прогон 13 новых проверок компактного окна, поверхностей и нагрева.
Новые регрессии проверяют семь вкладок, качество по умолчанию, изменяемые пороги,
дробный ввод, свойства/начальные поля, профили, ограничения стенок, размер XYZ,
VelocitySeed, отчёты зазора, TDC-файлы и неактивные черновики.
Исполняется Java-адаптер Second Order/SIMPLEC/Stopping Criteria на явных контрактах;
сгенерированный TDC компилируется против тестовых API-контрактов. Это не проверка
Siemens SDK. Реальные семь вкладок осмотрены на offscreen-снимках Qt.

## Компактное оформление и редактор поверхностей

Первую и вторую вкладки переработали в компактные формы. Длинные пояснения
перенесены в кнопки `?` с подсказками по наведению и пояснением по нажатию.
Флажок организации объектов называется «Папки объектов». Свойства и начальные
значения имеют ограниченную ширину; гравитация и направление расположены в строку.

Режим и турбулентность выбираются отдельно. RST доступен со стационарным и
нестационарным решателем; Hybrid SRH–SST требует нестационарного режима.
При IAPWS числовая сетка свойств скрывается, появляются селекторы транспортных
методов. Для каждого независимо доступны константа и IAPWS; классы методов взяты из пользовательской записи 2602.
Константы обновляются из текущего состояния калькулятора y+ автоматически при
изменении источника и по кнопке. Загрузка профиля не перезаписывается неизменившимся
источником калькулятора.

Функции `pi`, `Apert`, `thetaZ`, `seedX`, `seedY`, `VelocitySeed` и относительная
высота создаются автоматически. В начальной скорости можно выбрать VelocitySeed.
Функция назначается после её создания и до инициализации; повторный импорт не
перезаписывает начальные условия существующей задачи.

### Тепловой поток

В «Физике» флажок «Задать тепловой поток» открывает таблицу `q1 … qN` с точным
соответствием группам стенок. При изменении группировки таблица перестраивается:
сектора, физические стержни, стенки подканалов. Группы разных типов не смешиваются;
нагрев назначается только ТВЭЛ, НК и ИК исключены. Например, два подканала при
группировке по подканалу дают две строки, три — три строки.

В профиле сохраняются устойчивые идентификаторы групп и q, а не номера строк.
Неизвестная группа или изменившийся состав нагреваемых стенок блокирует экспорт.
Создаются параметры `qN`, функции `HeatFlux_qN` и назначения Heat Flux на соответствующие
границы через записанный FunctionScalarProfileMethod. Повторный запуск того же
макроса сохраняет изменения q, сделанные в STAR. Новое значение из вновь
экспортированного макроса обновляет параметр; возврат к более раннему значению
тоже обрабатывается. Чужие параметры с совпадающими именами не перезаписываются.

Выключенный флажок не назначает новые тепловые условия и не отменяет ранее
заданные пользователем условия в существующей симуляции. При включённом нагреве
требуется энергия. Для TDC нагрев теперь включается в «Физике»; все сектора одного
подканала должны иметь одинаковый q, Sub2 нагревается сильнее Sub1.

### Предпросмотр и интерфейсы

Предпросмотр построен по двумерным контурам фактических блоков. Он показывает
исходные области, стенки и внешние стороны; после Fuse внутренние линии остаются
пунктиром, но не выдаются за физические границы. Нажатие стенки выбирает её группу
в таблице q, нажатие внешней стороны — поверхность пары.

Для соседних раздельных подканалов таблица позволяет выбрать Internal либо Wall
(не соединять). После Fuse этот выбор неприменим: внутренние стыки объединены.
Для внешних поверхностей можно составлять пары Periodic с переносом. Проверяются
площадь, противоположность нормалей, совпадение формы после переноса и отсутствие
повторного использования. Вращательная периодичность не реализована. Произвольная
измерительная Plane Section не может быть выбрана как физическая граница.
Пары и отключённые внутренние сопряжения сохраняются в профиле и реально
передаются в макрос. Ориентацию и преобразование Periodic после импорта следует
проверить в STAR; фактический API 2602 в среде разработки недоступен.

У эталона TDC боковые пары задаёт его контроллер; общий редактор не добавляет
к ним дополнительные пары. Удалить ранее выбранные общие пары можно и при
включённом TDC.

Группировка и имена поверхностей используют новую схему идентификации. Поэтому
для общего экспорта после этой модернизации используйте новую пустую симуляцию
или её отдельную копию: макрос откажется менять несовместимую ранее импортированную
топологию. Изменение списка интерфейсов также требует новой совместимой сетевой
конфигурации; решение не переимпортируется молча.


### Запись дополнительных команд 2602

Источник — `addtion_command_macros.java`, добавленный пользователем в main
(fc995e6). Перенесены итоговые команды `IapwsDynamicViscosityMethod`,
`IapwsThermalConductivityMethod` и `FunctionVectorProfileMethod.setFieldFunction`.
Промежуточные переключения моделей, ошибочный `sin*`, недописанная ссылка `$t_end}`
и абсолютный путь импорта не переносятся.

Общий редактор осевых интерфейсов использует команды Fully Developed Periodic из записи.
`ReferenceDensity` и `MinimumAllowableWallDistance` доступны в опорных значениях.
Базовые Mass Flow Inlet / Pressure Outlet используют стандартные классы профилей;
для завершённой настройки входной турбулентности и обратного потока нужна запись
этих опций. Явная настройка вращательного преобразования требует записи оси/центра/угла
и примера пары. Автоматическое повторное назначение условий рассчитанной задачи
не включается без отдельного режима.

Проверка интеграции дополнительных команд: полный offscreen unittest — 228 тестов, OK (75,437 с). Реальный STAR-CCM+ не запускался.


### Опорные значения и дерево граничных поверхностей

`Minimum Allowable Wall Distance` задаётся в метрах, по умолчанию 1e-7 м.
Это ограничение физической модели, а не высота первой ячейки сетки. При гравитации
появляется `ReferenceDensity`: можно взять плотность из y+ либо задать отдельно.
Оба значения создаются как размерные параметры и назначаются опорным величинам.
Они применяются при первоначальной настройке; повторный импорт сохраняет физику.

В геометрии рядом со схемой расположено дерево реальных физических границ:
входы/выходы, стенки, боковые поверхности. После Fuse — один вход и один выход;
при отдельных регионах — свои для каждого подканала. Вход/выход показаны
отдельными кликабельными проекциями справа от поперечного сечения. Выбор в дереве
и на схеме синхронизирован; Ctrl добавляет вторую поверхность. Пунктирная рамка
Qt отключена, выделение показывает цвет линии. Пунктир исходных стыков Fuse
сохраняется как геометрическая информация, это не рамка выделения.

Одна поверхность: Wall, Symmetry, Mass Flow Inlet (кг/с), Pressure Outlet
(избыточное давление, Па). Температура массового входа берётся из T_init;
турбулентность и обратный поток требуют проверки в STAR. Две поверхности:
Internal для совпадающих граней, Internal + Periodic, Fully Developed + Periodic
с положительным расходом (кг/с). Для Fully Developed первой выбирается вход,
второй — выход того же региона. Настройки расхода пары сохраняются в параметре
PeriodicMassFlow_N. Повторное применение к той же паре обновляет её назначение.

Обычный Periodic оставляет стандартное преобразование STAR Rotational +
Translational: отдельного назначения оси/центра/угла в UI нет. До экспорта для
него проверяются площади; геометрическую трансформацию обязательно проверить в
STAR. Прежний вариант «только перенос» дополнительно проверяет нормали и форму.
Совпадающие соседние границы можно назначить явно; тогда они исключаются из
автоматического поиска сопряжений. Выбор Wall в таблице соседей также сохраняется.

Проверяются повторное использование поверхности, конфликт одиночного условия и
интерфейса, устаревшие имена после Fuse/группировки и конфликт с нагревом ТВЭЛ.
При обнаружении ошибки профиль не применяется и экспорт блокируется.
Новые условия и интерфейсы включены в отпечаток конфигурации: смена назначения
требует новой тестовой симуляции, а не скрытой перестройки существующей.
Для эталона TDC условия по-прежнему задаёт его контроллер. Общие потоковые
отчёты ещё используют измерительные сечения, а не отдельный выбор стороны
периодического интерфейса; это ограничение не изменено редактором границ.

Новые команды проверены генераторными регрессиями и Qt offscreen-тестами.
Реальный запуск новых типов границ, преобразования интерфейсов и опорных величин
в STAR-CCM+ 2602/компиляция с Siemens SDK в среде разработки не выполнялись.

Проверка редактора границ и опорных величин: полный offscreen unittest — 236 тестов, OK (86,866 с). Выполнены py_compile, git diff --check и осмотр Qt-снимков; Siemens SDK/STAR-CCM+ не запускались.

# TMC: макрос для эталонных двух подканалов, STAR-CCM+ 2602

Файл для STAR: **[TMC_Hybrid.java](TMC_Hybrid.java)**. Имя файла должно совпадать с именем класса. Это отдельное дополнение к уже импортированной эталонной сетке, а не новый импортёр. Оно не заменяет проверку сходимости и статистического установления.

**Статус проверки:** исходник компилируется на минимальных контрактах API, численная Java-логика проверяется выполнением; это не компиляция с Siemens SDK. STAR-CCM+ в среде разработки отсутствует. Первый запуск нужен на копии `.sim`; реальные вызовы API 2602, решение и знаки потоков должны быть проверены там. Неподдерживаемые обязательные вызовы останавливают действие с `[TMC ERROR]`, а не заменяются фиктивными результатами.

## Что требуется в симуляции

Использована предоставленная пользователем связка:

- `bundle_project_reference.json`: два подканала S18/S22, шаг 11,64 мм, твэл 9,1 мм, длина 300 мм, зазор 2,54 мм;
- `setup_starccm_subchannels_reference.java`: один регион `TVS_Assembly`, постоянные свойства, SRH/SST, ось Z, 11 сечений каждого исходного подканала;
- `addition_macros.java`: две боковые периодические пары, Fully Developed Mass Flow на торцах, нагрев;
- `addition_macros1.java`: знак HeatTransferReport и объёмный источник;
- Liu et al., *Turbulent Mixing Models and Other Mixing Coefficients*, Nuclear Technology 206 (2020), §V.B, формулы (35)–(42); формула (4) для опорного массового потока.

Перед запуском должны существовать регион и Derived Parts `Subchannel_1_Domain`, `Subchannel_2_Domain`, `Subchannel_i_Section_Z_0mm` ... `300mm` через 30 мм, `Gap_Sub1_Sub2`. Макрос проверяет их наличие, объёмы, положение по Y и площадь зазора. Он **специфичен для эталонного положения и геометрии**, не применяется к произвольной ТВС.

Поддерживаются исходные три rod-границы каждого подканала из эталона или уже объединённые `rod_s1`, `rod_s2`. Макрос не объединяет границы заново. Периодические интерфейсы переиспользуются по фактической паре границ; занятая другой парой граница вызывает отказ. Сопоставление/ориентацию периодических интерфейсов нужно проверить в STAR.

## Первый запуск

1. Сохранить отдельную копию тестовой `.sim`.
2. Выполнить `TMC_Hybrid.java`. При отсутствии параметров это **Action=0: настройка**, без расчёта и без инициализации.
3. Проверить сообщения `[TMC ERROR]` / `[TMC OPTIONAL]`, папки TMC и файл `TMC_setup_manifest.txt` рядом с симуляцией.
4. Проверить в интерфейсах боковую периодичность и осевую Fully Developed Periodic Mass Flow.
5. Проверить физику: SRH/SST и Segregated Fluid Temperature должны быть заранее созданы эталонным макросом. Схемы дискретизации, внутренние итерации и критерии решателя сохраняются; их пригодность для HYBRID этим макросом не доказывается.

Настройка назначает постоянные свойства, тепловые потоки и сток через собственные параметры/отчёты. Значения по умолчанию:

| Параметр | Значение |
|---|---:|
| `TMC_Rho` | 747,33908055 кг/м³ |
| `TMC_Mu` | 9,271750031·10⁻⁵ Па·с |
| `TMC_Cp` | 5225,098 Дж/(кг·К) |
| `TMC_Lambda` | 0,575327567 Вт/(м·К) |
| `TMC_HeatFlux_Sub1` | 10 000 Вт/м² |
| `TMC_HeatFlux_Sub2` | 300 000 Вт/м² |
| `TMC_MassFlow` | 0,1325444593 кг/с **на всё сечение** |
| `TMC_TimeStep` | 2,5·10⁻⁵ с |
| `TMC_EquivalentGapCount` | 3 |

Положительный нагрев жидкости соответствует отрицательному HeatTransferReport на rod-границах. Источник назначается как `${TMC_qvSourceReport}`, сам отчёт равен `${TMC_WallHeatSigned_AllReport}/${TMC_Volume_AllReport}`. Ожидаемые контрольные величины: суммарный нагрев около 1329,36 Вт, источник около −8,4726·10⁷ Вт/м³. Знак проверить в STAR до накопления статистики.

Чужие объекты с совпавшими именами не перезаписываются. Повторная настройка сохраняет существующие собственные параметры, решение и файлы серий, но повторно назначает управляемые физические связи. Пользовательские правки этих связей вне параметров TMC могут быть заменены повторной настройкой.

## Управление отрезками расчёта

Изменить `TMC_Action` в Automation → Parameters, затем снова выполнить **тот же** Java-файл. После действия Action возвращается в 0, чтобы случайно не повторить длительный запуск.

| Action | Действие |
|---:|---|
| 0 | Создать/обновить настройку; не запускать расчёт |
| 1 | Заморозить энергию и продвинуть гидродинамику на `TMC_HydroDuration` |
| 2 | Включить энергию и продвинуть тепловой разгон на `TMC_ThermalDuration` |
| 3 | Начать **новую** статистическую серию, без временных шагов |
| 4 | Добавить `TMC_BlocksToRun` статистических блоков длительностью `TMC_BlockDuration` |
| 5 | Пересчитать общую статистику по сохранённым блокам, без CFD-шагов |
| 6 | Вывести состояние |

Длительности — **секунды от текущего времени**, не абсолютные времена остановки. Начальные значения всех трёх длительностей — 0,45 с; `BlocksToRun=1`. Это удобные короткие отрезки управления, **не доказательство достаточного разгона/статистики**. Можно менять длительность и число блоков между запусками. Существующие остановочные критерии STAR могут прервать продвижение; отсутствие роста физического времени останавливает макрос.

Порядок:

1. Action=1, при необходимости повторять. Контролировать расход, сопротивление и развитые пульсации.
2. Action=2, при необходимости повторять. Контролировать **разность температур подканалов**, а не только общую температуру, которую стабилизирует сток.
3. После собственной проверки установления поставить `TMC_AllowStatistics=1` и выполнить Action=3.
4. Например, задать `TMC_BlockDuration=0.45`, `TMC_BlocksToRun=5`, выполнить Action=4.
5. Проверить блоковые значения DeltaT, обмена, невязок и TMC; при необходимости увеличить длительность блоков/добавить блоки.

Гидродинамический/тепловой разгон снова сбрасывает разрешение статистики. Если между блоками время продвигалось вручную или другими действиями, продолжать старую серию нельзя: Action=4 обнаруживает разрыв **до следующего расчётного блока**. Нужна новая серия Action=3. Физические параметры и управляемые определения также защищены отпечатком серии; изменение требует новой серии. Нельзя незаметно менять модель/граничные условия вне параметров TMC: отпечаток не является полным дампом всех настроек STAR.

Макрос выполняет `step(1)` и проверяет реальное продвижение физического времени. Окончание отрезка может превысить заданное время на последний физический шаг; используются фактические времена, не округлённые номера шагов. `TMC_MaxStepsPerAction` ограничивает число вызовов продвижения. Автоматический CFL-регулятор шага не создаётся.

## Отчёты и мониторы

Папки TMC: Geometry, Flow, Thermal, Balances, Mixing, Wall, Statistics, Numerics; параметры — Control и Physical. Если групповой API отличается, макрос сообщает это; отчёты не подменяются пустыми папками.

**Без мониторов:** объёмы, площади всех сечений, площади rod-стенок, смоченные периметры, гидравлические диаметры, площадь зазора, Re/Pr, промежуточные функции.

**Мгновенные отчёты с мониторами:** расходы в начальных/конечных сечениях, среднемассовые температуры с усреднением по длине, объёмные температуры для диагностики, нагрев/сток, запас чувствительной энергии, потоки чувствительной энергии, массовые невязки, осевое трение, давления, обмен без накопления, разности температур, опорная массовая скорость, расход и адвекция через общий зазор. Total Enthalpy и его потоки — дополнительные диагностические отчёты при наличии поля. CFL Max создаётся при наличии поля ConvectiveCourantNumber, объёмный CFL — без отдельного монитора.

Все потоки вычисляются по **мгновенным полям**. Нельзя заменять средний поток энтальпии произведением отдельных средних расхода и энтальпии. Нативные мониторы настроены по физическим шагам; CSV статистики снимается после возвращения `step(1)`.

Массовые балансы подканалов включают торцы, внутренний зазор и внешние периодические стороны. Нормали внешних сторон заданы аналитически для данной эталонной геометрии, поэтому макрос не универсален.

Основной энергетический баланс относится к **чувствительной тепловой энергии** Segregated Fluid Temperature:

`E_i = integral_V rho Cp (T − Tref) dV`

`Fz_i = integral_out rho uz Cp(T − Tref) dA − integral_in rho uz Cp(T − Tref) dA`

`X_i_NoStorage = Qwall_into_fluid_i + Qvolume_i − Fz_i`

Средний обмен наружу из горячего Sub2:

`Qhot = mean(X_2_NoStorage) − (E_2(end) − E_2(start))/duration`.

Невязка всей области с накоплением получается аналогично. Осевое диффузионное сокращение предполагается по периодичности; механическая полная энергия, работа давления и вязкая диссипация не выдаются за проверенные этим тепловым балансом члены. Дополнительные потоки Total Enthalpy не смешиваются с запасом чувствительной энергии.

## TMC и температура

Основное определение — среднемассовая температура каждого из 11 сечений, затем трапецеидальное усреднение по длине. Sub2 горячий, DeltaT = Sub2 − Sub1. Объёмная температура даёт отдельный диагностический коэффициент; два определения не смешиваются.

`Gref = (massflow_1 + massflow_2)/(A_1 + A_2)`

`TMC_Effective = Qhot_mean / (N_gap * s * L * Cp * Gref_mean * DeltaT_length_mean)`

Это адаптация энергетического метода статьи к периодическому HYBRID, а не буквальное воспроизведение её стационарного примера с адиабатическими стенками. Деление на 3 предполагает эквивалентность трёх путей обмена; её нужно подтвердить потоками/симметрией. Эффективный коэффициент включает молекулярный перенос и возможный перенос средними течениями.

`TMC_EnableOptionalGapConduction=1` добавляет диагностический молекулярный поток `−lambda grad(T)[1]` через общий зазор. Поддержку этого выражения нужно проверить в 2602. Тогда дополнительно выводится `TMC_MolecularCorrected`; он всё ещё не отделяет среднюю конвекцию от разрешённых турбулентных корреляций. Отрицательная поправленная величина требует проверки, не исправляется abs/clamp.

При малой DeltaT (`TMC_MinDeltaT`, по умолчанию 0,01 К), неправильном направлении горячего обмена, нечисловых отчётах или отрицательном опорном расходе блок не признаётся корректным.

## Временные средние и файлы

Скалярные отчёты интегрируются методом трапеций с **фактическим dt**. Итоговый TMC — отношение средних за общий интервал, а не среднее мгновенных TMC и не невзвешенное среднее блоков.

Каталог рядом с `.sim`: `TMC_series_<ID>`:

- `configuration.txt` — физические параметры и определения серии;
- `block_00001.csv` и т.д. — мгновенные значения с физическим временем;
- `blocks.csv` — TMC, DeltaT, Gref, накопление и невязки каждого блока;
- `summary.csv` — общие временные средние, стандартные отклонения и итоговые показатели.

`TMC_LastBlock_*` и `TMC_Mean_*` — скалярные отчёты результатов. Они обновляются после блока/выгрузки и не имеют лишних временных мониторов. Накопление энергии определяется по концам интервала. Точность трапецеидального интегрирования зависит от временного разрешения; это не точное воспроизведение внутреннего дискретного баланса решателя.

Незавершённый блок остаётся `.partial.csv` и не входит в итоговую статистику. Старые серии не удаляются. При аварии между записью CSV и обновлением счётчика может потребоваться ручное восстановление по файлам; повторный запуск не перезаписывает обнаруженный блок.

Независимая проверка CSV на компьютере с Python:

```bash
python -m tmc.analyse_series "путь/к/TMC_series_ID" --output result.json
```

Она проверяет непрерывность блоков, одинаковость общей граничной выборки, фактические dt, накопление и отношение средних. Разброс блоков не называется доверительным интервалом без проверки независимости и установления.

## Дополнительные средние поля

По умолчанию `TMC_CreateFieldMeans=0`: для балансового TMC достаточно скалярной статистики, без дополнительных объёмных полей на 26,4 млн ячеек.

Если поставить 1 **до Action=3**, создаются отдельные средние поля текущей серии: Velocity (вектор), Pressure, Temperature, WallShearStress (вектор на стенках), TotalEnthalpy. Предыдущие пользовательские средние не сбрасываются. Нативный API паузы проверяется; если он отсутствует, создание останавливается, нужно оставить флаг 0 и передать записанный пример управления FieldMeanMonitor. При работающем API полевые средние включены только во время Action=4.

Эти нативные полевые средние требуют **постоянного dt на всю серию**. Изменение dt запрещено отпечатком/проверкой реального шага. При флаге 0 скалярная статистика использует фактические интервалы и допускает изменение TimeStep между блоками. Поля произведений и RMS-корреляций не создаются в базовом балансовом наборе.
